# 文档地图

本文件是本项目所有文档的入口。写文档前先在此定位归属，避免同类文档散落。

## 项目定位

Windows 平台的**键鼠辅助工具**：用户自定义"任务"；一个任务由若干**命令**（键盘 / 鼠标操作）组成，运行时这些命令**并行、各自按自己的点按频率重复**；通过自定义的**开关按键**以点按方式启停任务。

## 目录结构

```
docs/
├── README.md                        本文件——文档地图
├── requirements/

│   └── 待确认问题.md                 待用户决策的遗留问题清单（当前为空）
└── design/
    └── 设计文档.md                   总体设计（技术选型 / 架构 / 执行模型 / 界面 / 配置 / 验证方式）
```

## 分层约定

- **需求层**（`requirements/`）回答"要什么"，不写技术选型与实现方案。
- **设计层**（`design/`）回答"怎么做"；技术选型与实现方案只写在此层，不复述需求内容。
- **测试层**（`tests/` 或设计层内的验证章节，待建）回答"如何验证"；设计文档 §13 只声明验证方式与 AC 的对应关系，**独立的验收测试文档尚未建立**。

同一机制只在**一个**文档中详述，其他文档引用而不复述。
