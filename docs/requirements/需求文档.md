## 1. 目标与非目标

### 1.1 目标

提供一个 Windows 常驻工具，让用户**自定义任务**；一个任务由若干条**键盘 / 鼠标命令**组成，这些命令在任务运行期间**并行、各自独立地按自己的频率重复**；用户通过**自定义的开关按键**以**点按**方式启停任务，从而把手动的重复键鼠操作交由工具代劳。

### 1.2 非目标（本期明确不做）

以下内容本期**不实现**，避免范围蔓延。它们不是"以后再说"，而是**本版本需求范围之外**：

| 编号 | 非目标 | 说明 |
|---|---|---|
| N1 | 改键 / 键位重映射 | 本工具只**模拟输出**键鼠操作，不改变用户实体按键原本的输入结果 |
| N2 | 键盘宏录制回放 | 不采集用户真实操作轨迹并回放；任务的命令由用户手工配置 |
| N3 | 跨平台 | 本期只支持 Windows |
| N4 | 条件触发 / 图像识别 / 定时调度 | 本期触发方式只有"点按开关按键"，不做"当屏幕出现 X 时执行"、"每天 9 点执行" |
| N5 | 脚本编程能力 | 不提供脚本语言 / 表达式；任务模型是结构化的命令集合 |
| N6 | 云端同步 / 账号体系 | 配置仅存本机，不做多机同步 |
| N7 | 对抗反作弊、绕过检测 | 本工具定位为通用效率辅助，不针对特定软件做规避设计（见 §6.3） |
| N8 | 启动时自动运行任务 | 本期**不支持**"软件启动后自动开跑某任务"，任务一律由用户手动点按开关键启动 |
| N9 | 命令分组 / 子任务 | 本期**不支持**任务嵌套或任务调用任务；一个任务就是一层的扁平命令集合 |

## 2. 术语定义

本文档使用以下术语，全文含义一致：

| 术语 | 定义 |
|---|---|
| **任务（Task）** | 用户定义的一个可启停单元，包含一个**命令集合**、一个**开关按键** |
| **命令（Command）** | 任务中的一条操作项，类型为键盘操作或鼠标操作（见 §4.4） |
| **点按（Tap）** | 命令的一种执行形态：按下后**立即**松开（即"敲击"），并**按该命令配置的频率反复执行** |
| **按住（Hold Down）** | 命令的一种执行形态：只发出"按下"事件，**一直保持按住**，直到任务停止时由工具自动补发松开 |
| **开关按键（Toggle Key）** | 绑定到某个任务的实体按键（键盘键或鼠标键），**点按**它即切换该任务的运行/停止状态 |
| **并行执行** | 任务运行时，其全部命令**同时**处于活动状态，各自按自己的节奏重复，互不排队 |
| **点按频率（Tap Frequency）** | **每条点按形态的命令**各自持有的参数：该命令每秒点按的次数，单位为**次/秒**（见 §4.5） |
| **运行中（Running）** | 任务处于"命令并行重复执行"的状态 |
| **已停止（Stopped）** | 任务不在执行任何命令的状态 |

## 3. 用户与场景

### 3.1 目标用户

需要**重复性键鼠操作**的 Windows 普通用户，且**不具备编程能力**——必须通过图形界面配置，不写代码。

### 3.2 典型场景

| 编号 | 场景 | 任务内容 | 开关按键 |
|---|---|---|---|
| S1 | 连续点击 | `鼠标左键·点按`，频率 10 次/秒 | `F6` |
| S2 | 按键保持 + 连点 | `键盘A·按住` ＆ `鼠标左键·点按`，频率 5 次/秒 | `F7` |
| S3 | 键鼠混合连招 | `键盘Ctrl·按住` ＆ `键盘C·点按`，频率 2 次/秒 | `鼠标侧键X1` |

> 注：同一任务内的多条命令以 `＆` 相连，表示它们**并行**（S2 中 A 键全程按住，同时左键在连点；S3 中 Ctrl 全程按住，同时 C 键在连按）。
> S3 的效果是"按住 Ctrl 连打 C"；若用户想要一次性的 `Ctrl+C`，应改用**组合键命令**（FR-CMD-K2），而非两条并行命令。

### 3.3 使用流程（用户视角）

1. 打开工具，进入任务管理界面；
2. 新建任务，起名（如"连点"）；
3. 向任务中添加命令，逐条设置类型与参数；
4. 为每条**点按形态**的命令设置点按频率；
5. 为任务指定**开关按键**；
6. 保存任务；
7. 在任意软件中，点按该开关按键 → 任务开始并行执行其全部命令；
8. 再次点按同一按键 → 任务停止，所有"按住中"的键被自动松开。

## 4. 功能需求

> 需求编号规则：`FR-<主题>-<序号>`。每条需求均可被 §7 的验收标准验证。

### 4.1 任务管理

| 编号 | 需求 |
|---|---|
| FR-TASK-01 | 用户可以**创建**任务，任务至少包含：名称、命令集合、开关按键 |
| FR-TASK-02 | 用户可以**编辑**已有任务的全部可配置项 |
| FR-TASK-03 | 用户可以**删除**任务；删除前需二次确认 |
| FR-TASK-04 | 用户可以**复制**任务（用于快速创建相似任务） |
| FR-TASK-05 | 任务列表持久化保存，**重启软件后任务配置不丢失** |
| FR-TASK-06 | 任务名称在列表中唯一；若用户使用重名，需提示并拒绝保存或要求改名 |
| FR-TASK-07 | 任务可被**单独启用/禁用**：被禁用的任务不响应其开关按键 |
| FR-TASK-08 | 同一任务不允许存在两个正在运行的实例（重复点按开关按键只做开/关切换，不叠加） |
| FR-TASK-09 | 同时运行的任务数量**不设上限**，可同时运行任意数量的任务，互不影响 |

### 4.2 开关按键

| 编号 | 需求 |
|---|---|
| FR-TOGGLE-01 | 用户可为任务指定**一个**开关按键；按键来源可以是键盘按键，也可以是鼠标按键（左/右/中/侧键 X1/X2） |
| FR-TOGGLE-02 | 开关按键的指定方式为**按键捕获**：用户点击"录制按键"后按下想用的键，界面显示捕获到的键名——**不允许手输键名**（避免拼写错误） |
| FR-TOGGLE-03 | 开关按键的行为固定为**点按切换**：运行中 → 点按 → 停止；已停止 → 点按 → 运行 |
| FR-TOGGLE-04 | 界面需**实时显示**每个任务的当前状态（运行中 / 已停止） |
| FR-TOGGLE-05 | 一个开关按键**最多只能绑定一个任务**；若用户为不同任务指定了同一个按键，保存时需提示冲突并拒绝（或要求用户先解绑）。判据是**按键本身**（主键），**不区分修饰键**：`F8`、`Ctrl+F8`、`Alt+F8` 视为同一个开关按键，三者间任意两者共存都拒绝（口径与理由见设计文档 §3.4.1）。校验范围**含已禁用任务** |
| FR-TOGGLE-06 | 开关按键必须支持**全局生效**：焦点不在本工具窗口时，点按开关按键仍能启停任务 |
| FR-TOGGLE-07 | **开关按键与任务内命令不得重叠**：若开关按键同时被配置为该任务命令集合内的实体键命令，则保存时拒绝并提示（否则 §6.1 的"开关按键被工具消费"与 FR-TAP-03 的"保持按住"会在同一实体键上直接冲突） |

### 4.3 命令集合与执行模型

| 编号 | 需求 |
|---|---|
| FR-SEQ-01 | 任务包含一个**命令集合**；集合内的命令**无先后依赖**（并行执行），界面中仅需列出与增删改，**不提供排序** |
| FR-SEQ-02 | 任务运行时，集合内的命令**全部同时启动**、各自独立重复执行 |
| FR-SEQ-03 | 每条命令的重复动作**持续进行**，直到任务被停止；任务自身**无轮次概念**、**无轮间隔** |
| FR-SEQ-04 | 不同命令之间的**相对时序不作保证**（各自按自己的频率独立推进） |
| FR-SEQ-05 | 每条命令在其单次动作完成后，间隔一个**自身频率对应的周期**（1/频率 秒）再执行下一次（频率的定义见 FR-TAP-04） |
| FR-SEQ-06 | 任务停止时，**立即**终止后续命令的执行；不得在停止后继续发出键鼠操作 |
| FR-SEQ-07 | 任务停止时，若存在"按住形态"的命令（已按下未松开），**必须补发松开事件**，避免按键卡在按下状态 |
| FR-SEQ-08 | 任务**不允许保存为空任务**（命令集合为空）：保存时拒绝并提示，避免产生一个点了没反应的开关按键 |
| FR-SEQ-09 | 命令集合必须支持**新增 / 删除 / 修改**单条命令 |
| FR-SEQ-10 | 一个任务中，**同一实体键不允许同时存在"按住"与"点按"两条命令**（会产生自相矛盾的按键状态）：保存时拒绝并提示 |

### 4.4 命令类型

任务中的每条命令属于以下类型之一。**点按 / 按住**是键盘命令与鼠标按键命令的**通用执行形态**（见 §4.5）。

**键盘命令**

| 编号 | 命令类型 | 参数 |
|---|---|---|
| FR-CMD-K1 | 键盘按键 | 按键（按键捕获指定） |
| FR-CMD-K2 | 组合键 | 修饰键（Ctrl / Shift / Alt / Win，可多选）+ 主键 |

**鼠标命令**

| 编号 | 命令类型 | 参数 |
|---|---|---|
| FR-CMD-M1 | 鼠标移动 | 目标坐标 (x, y)；坐标为屏幕**绝对坐标** |
| FR-CMD-M2 | 鼠标按键 | 按键（左 / 右 / 中 / 侧键 X1 / X2） |
| FR-CMD-M3 | 鼠标滚轮 | 方向（上 / 下）+ 格数 |

> M1/M3 为瞬时操作，无点按/按住形态，但需配置**自身重复频率**（见 FR-TAP-07）。

### 4.5 点按与按住

| 编号 | 需求 |
|---|---|
| FR-TAP-01 | 键盘按键命令与鼠标按键命令，其执行形态可配置为**点按**或**按住** |
| FR-TAP-02 | **点按**＝按下后立即松开（间隔趋近于 0），并按该命令的**点按频率**反复执行 |
| FR-TAP-03 | **按住**＝只发出按下事件，**保持按住状态不松开**；不配置任何时长参数 |
| FR-TAP-04 | **点按频率**是**每条点按命令各自持有**的参数，表示该命令每秒点按的次数（单位为**次/秒**）；不同命令的频率**互不影响** |
| FR-TAP-05 | 点按频率需有**有效范围校验**，超出范围时拒绝保存并提示（合法范围：**1~1000 次/秒**） |
| FR-TAP-06 | 组合键命令（FR-CMD-K2）的执行形态为：修饰键按下 → 主键执行（点按/按住）→ 修饰键松开；若为点按形态，整个组合按该命令的频率反复执行；若为按住形态，任务停止时按**主键先松开、修饰键后松开**的顺序补发（避免修饰键先松导致主键被当作单键发出） |
| FR-TAP-07 | 鼠标移动（FR-CMD-M1）与滚轮（FR-CMD-M3）为**瞬时操作**，不适用点按/按住形态；其在任务运行期间按**自身重复频率**重复执行（两者各自持有一个频率参数，字段同 FR-TAP-04 的点按频率） |
| FR-TAP-08 | **按住**形态的命令，其松开由工具在任务停止时统一补发（FR-SEQ-07），用户不需要额外配置"松开"命令 |

### 4.6 运行控制与安全停止

| 编号 | 需求 |
|---|---|
| FR-RUN-01 | 提供**全局紧急停止**功能：一个独立的、可在设置中配置的快捷键，按下后**停止所有正在运行的任务** |
| FR-RUN-02 | 紧急停止快捷键**必须有默认值**（不可为空），保证开箱即用；默认为 `Ctrl+Alt+F12` |
| FR-RUN-03 | 紧急停止快捷键不得与其他任务的开关按键冲突 |
| FR-RUN-04 | 软件需提供**一键停止全部任务**的界面按钮 |
| FR-RUN-05 | 软件退出时，**必须**停止所有运行中的任务并补发未松开的按键事件（同 FR-SEQ-07） |
| FR-RUN-06 | 用户启用紧急停止快捷键时，若该快捷键与系统或其他软件已占用，需提示用户该键可能不可用，或引导其更换 |
| FR-RUN-07 | 紧急停止快捷键与某个任务的开关按键**相同时**，该按键**不得被吞掉**（用户仍能收到它）；且按下即停止全部任务。冲突在保存期即被拒绝（FR-RUN-03），故正常使用下该状态不可达 |

### 4.7 后台常驻与界面

| 编号 | 需求 |
|---|---|
| FR-UI-01 | 软件支持**最小化到系统托盘**；关闭主窗口时默认隐藏到托盘而非退出 |
| FR-UI-02 | 托盘图标提供菜单：显示主窗口 / 停止全部任务 / 退出软件 |
| FR-UI-04 | 为需要**固定取值的配置项**（命令类型、鼠标按键、滚轮方向、执行形态等）提供**选择控件**（下拉 / 单选 / 按钮），不得要求用户手输 |
| FR-UI-05 | 界面需具备中文语言（本期**只做中文**，不引入多语言架构） |

### 4.8 配置持久化

| 编号 | 需求 |
|---|---|
| FR-CFG-01 | 任务、设置等全部配置存储在本机（路径为 `%APPDATA%\<软件名>\`），用户关闭并重启软件后配置完整保留 |
| FR-CFG-02 | 配置文件损坏或不可读时，软件**不得崩溃**；应提示错误并回退到可用的空配置 |
| FR-CFG-03 | 软件升级后应能读取旧版本配置文件（向后兼容），或在不可兼容时给出明确提示 |
| FR-CFG-04 | 本期**不提供**配置文件的导入/导出功能 |
| FR-CFG-05 | 软件提供**简单运行日志**（任务启停、错误事件），便于排查问题 |

## 5. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-01 | 触发响应 | 点按开关按键后，任务启动延迟（从按键事件到第一条命令发出）应 ≤ 50ms |
| NFR-02 | 点按频率精度 | 在 **1~50 次/秒**的频率区间内，各命令实际点按间隔与其配置频率的误差应 ≤ ±20ms（即配置 100ms 间隔时，实际间隔在 80~120ms 之间）；该指标在多命令并行时仍需满足。**50 次/秒以上（间隔 <20ms）不适用 ±20ms 误差带**——该区间误差带将大于间隔本身，数学上无意义；此时以"实际平均频率不低于配置值的 90%"为替代指标。区间边界 50 次/秒为初值，实现期经实测（设计文档 V-2）校准后如有调整，须经本需求文档变更流程确认 |
| NFR-03 | 并行隔离 | 一条命令的频率或其执行耗时的变化，不得影响其他命令的频率精度（见 NFR-02） |
| NFR-04 | 资源占用 | 空闲（无任务运行）时 CPU 占用应接近 0%；内存占用应保持稳定，长时间运行（≥8 小时）不持续增长 |
| NFR-05 | 稳定性 | 连续运行 8 小时以上不崩溃、不出现任务"跑飞"（命令持续发出但界面显示已停止） |
| NFR-06 | 权限 | 工具需要**全局键鼠钩子**与**模拟输入**能力，正常启动路径为**管理员权限**（清单无条件请求提权）。需求上要求：当提权被拒（用户取消 UAC / 策略禁止）导致无法以管理员身份运行时，需**明确告知用户**如何解决，而非静默失效 |
| NFR-07 | 不干扰 | 工具自身不产生可见的输入副作用；被禁用的任务、以及未运行时，不得向系统发出任何模拟输入 |
| NFR-08 | 可关闭性 | 用户必须能**随时**通过托盘菜单或紧急停止快捷键终止工具的输入输出行为（见 FR-RUN-01、FR-UI-02） |
| NFR-09 | 单实例 | 软件同一时刻只允许运行一个实例，防止重复启动造成开关按键被双重响应 |
| NFR-10 | 界面风格 | 采用 **Windows 原生视觉风格**：控件外观遵循系统原生规范，使用系统主题色，随系统深色/浅色主题自动切换；界面**简约**——只呈现必要元素，无冗余装饰、无自设皮肤 |
| NFR-11 | 界面动画 | 状态切换（任务启停、保存成功/失败、窗口显示隐藏）配有**过渡动画**；动画不得阻塞操作响应；当系统开启"减少动画"设置时，动画应相应减弱或关闭 |

## 6. 边界与约束

### 6.1 与用户实体输入的交互

用户点按**开关按键**时，该按键会被工具"消费"用于切换任务状态。需求上**要求**：

- 开关按键自身的**原始输入结果如何处理**（是照常发给系统 / 还是被工具吞掉），同一任务内需**保持一致**——不能出现“有时生效有时不生效”；
- 该行为作为一项**可配置选项**暴露给用户，**逐任务配置**（在任务编辑页设置），默认值为“照常发送给系统”。

### 6.2 多任务并发

- 允许多个任务同时处于运行状态（各有各的开关按键）；**同时运行的任务数量不设上限**；任务之间**互不互斥**——任务 A 运行时点按任务 B 的开关键，只切换 B 的状态，不影响 A；
- 多个任务同时发出键鼠操作时，其**交错时序不做保证**（属于实现层问题，需求上只要求各任务自身的各条命令频率不失真）；
- 紧急停止与"停止全部"按钮必须能一次性停下**所有**任务。

### 6.3 使用边界声明

本工具模拟键鼠输入。用户将其用于**违反第三方软件服务条款**的场景（如游戏自动化）所产生的后果，由用户自行承担。工具本身**不针对任何特定软件做规避、隐藏或反检测设计**（见非目标 N7）。

### 6.4 环境约束

- 仅支持 Windows（最低 **Win10 1809**）；
- 单显示器与多显示器环境下，鼠标绝对坐标均需正确工作。
